## Обзор проекта

**Danilov** — это современный e-commerce сайт для премиальной обуви ручной работы из Азербайджана. Проект представляет собой одностраничное приложение (SPA), построенное на React, с поддержкой трех языков (азербайджанский, русский, английский) и интеграцией с headless CMS Sanity для управления контентом.

### Ключевые особенности:
- 🌍 **Мультиязычность**: Поддержка 3 языков (az, ru, en) с URL-префиксами
- 🛍️ **E-commerce функционал**: Каталог товаров, категории, страницы продуктов
- 📱 **Адаптивный дизайн**: Полностью responsive интерфейс
- ⚡ **Производительность**: Оптимизация загрузки, code splitting, lazy loading
- 🔍 **SEO-оптимизация**: Структурированные данные, мета-теги, hreflang
- 🎨 **Современный UI**: Tailwind CSS, кастомные компоненты

## Архитектура приложения

### Тип архитектуры: **Component-Based Architecture**

Приложение построено по принципу компонентной архитектуры с использованием:
- **Context API** для глобального состояния
- **Custom Hooks** для переиспользуемой логики
- **Layout Components** для структуры страниц
- **Page Components** для отдельных страниц
- **Reusable Components** для UI элементов

### Поток данных:
```
Sanity CMS → React Context → Components → UI
```

## Маршрутизация и навигация

### Структура маршрутов:

Приложение использует **языковые префиксы** в URL для поддержки мультиязычности:

```
/                    → редирект на /az
/:lang               → главная страница (az, ru, en)
/:lang/category/:category → страница категории
/:lang/product/:sku  → страница товара
/:lang/gift-card     → подарочные карты
/:lang/contacts      → контакты
/:lang/service       → услуги
/:lang/culture       → культура/история
/:lang/sale          → распродажа
```

### Реализация роутинга:

**App.jsx** — основной роутер:
```javascript
- Корневой путь "/" редиректит на "/az" (азербайджанский по умолчанию)
- Все маршруты обернуты в SiteLayout компонент
- SiteLayout валидирует язык из URL и синхронизирует с контекстом
- Неподдерживаемые языки редиректятся на дефолтный
```

**SiteLayout.jsx** — валидация языка:
- Проверяет наличие языка в URL
- Валидирует поддерживаемые языки (az, ru, en)
- Синхронизирует язык из URL с LanguageContext
- Рендерит Header, Footer и Outlet для дочерних маршрутов

### Особенности навигации:

1. **Header компонент** (820 строк) — сложная навигация:
   - Десктопное выпадающее меню с категориями
   - Мобильное меню с многоуровневой навигацией
   - Поиск с overlay модальным окном
   - Динамическое скрытие/показ при скролле
   - Интеграция с WhatsApp для контактов

2. **ScrollToTop** — автоматическая прокрутка вверх при смене маршрута

## Интернационализация (i18n)

### Поддерживаемые языки:
- **az** (азербайджанский) — основной язык, дефолтный
- **ru** (русский)
- **en** (английский)

### Реализация:

#### 1. LanguageContext (`src/context/LanguageContext.jsx`)
- Хранит текущий язык в состоянии
- Сохраняет выбор в `localStorage`
- Предоставляет функции:
  - `setLanguage(lang)` — установка языка
  - `toggleLanguage()` — переключение между языками
  - `getLocalizedPath(path)` — генерация пути с языковым префиксом
  - `isValidLang(lang)` — валидация языка

#### 2. Translations (`src/translations/index.js`)
- Централизованный объект с переводами
- Структура: `translations[language][section][key]`
- Используется во всех компонентах через `translations[language]`

#### 3. URL-based i18n
- Язык определяется из URL параметра `:lang`
- При смене языка URL обновляется автоматически
- Сохраняется выбор языка в localStorage

#### 4. SEO для мультиязычности
- **Hreflang теги** для всех языковых версий
- **Canonical URLs** для каждой страницы
- **Локализованные мета-теги** (title, description)

## Управление состоянием

### Context API используется для:

#### 1. LanguageContext
```javascript
- language: текущий язык (az, ru, en)
- setLanguage: функция установки языка
- getLocalizedPath: генерация локализованных путей
- supported: массив поддерживаемых языков
```

#### 2. CategoryContext
```javascript
- categories: массив категорий из Sanity
- loading: состояние загрузки
- Загружает категории при монтировании провайдера
```

### Локальное состояние:
- Используется `useState` для локального состояния компонентов
- `useEffect` для side effects (загрузка данных, подписки)
- `useMemo` для мемоизации вычислений (например, в Header)
- `useRef` для DOM ссылок и значений без ре-рендера

### Загрузка данных:
- Данные загружаются через `useEffect` в компонентах
- Используется Sanity client для запросов
- Состояние загрузки управляется локально в компонентах

## Интеграция с Sanity CMS

### Конфигурация клиента (`src/sanity/clients.ts`):
```typescript
- projectId: из переменных окружения
- dataset: из переменных окружения
- apiVersion: "2025-12-25"
- useCdn: true (для производительности)
```

### Типы данных в Sanity:

#### 1. **shoes** (товары)
- `title_en`, `title_az`, `title_ru` — названия
- `description_en`, `description_az`, `description_ru` — описания
- `price` — цена
- `sku` — артикул (используется в URL)
- `slug` — slug для URL
- `mainImage` — главное изображение
- `additionalImage1-5` — дополнительные изображения
- `categories` — связи с категориями

#### 2. **category** (категории)
- `slug` — slug категории
- `title_en`, `title_az`, `title_ru` — названия
- Используется для фильтрации товаров

#### 3. **info** (информация)
- `phone_number` — телефон для WhatsApp

### Примеры запросов:

#### Загрузка товаров по категории:
```javascript
const PRODUCTS_QUERY = `*[
  _type == "shoes" &&
  count(categories[@._ref in $catIds]) > 0
]{
  _id, title_en, title_az, title_ru,
  price, "slug": slug.current, sku,
  mainImage, additionalImage, categories
} | order(_createdAt desc)[0...6]`;
```

#### Загрузка конкретного товара:
```javascript
const PRODUCT_QUERY = `*[_type == "shoes" && sku == $sku][0]{
  _id, title_en, title_az, title_ru,
  price, sku, mainImage,
  additionalImage1-5,
  categories[]->{ _id, title, "slug": slug.current }
}`;
```

### Оптимизация изображений:
- Используется `@sanity/image-url` для генерации URL
- Автоматическая оптимизация размеров и форматов
- Поддержка WebP формата

## Ключевые технические решения

### 1. **Языковые префиксы в URL**
**Проблема**: Нужна поддержка нескольких языков с SEO-friendly URLs  
**Решение**: Использование префиксов `/az/`, `/ru/`, `/en/` в URL  
**Преимущества**: 
- SEO-friendly URLs
- Понятная структура для пользователей
- Легко делиться ссылками на конкретную языковую версию

### 2. **Headless CMS (Sanity)**
**Проблема**: Нужна гибкая система управления контентом  
**Решение**: Использование Sanity CMS  
**Преимущества**:
- Разделение контента и кода
- Легкое обновление контента без деплоя
- API-first подход
- Встроенная оптимизация изображений

### 3. **Context API вместо Redux**
**Проблема**: Нужно управление глобальным состоянием  
**Решение**: React Context API  
**Преимущества**:
- Меньше зависимостей
- Простота для небольшого проекта
- Встроено в React
- Достаточно для текущих потребностей

### 4. **Vite вместо Create React App**
**Проблема**: Нужна быстрая сборка и HMR  
**Решение**: Vite как сборщик  
**Преимущества**:
- Мгновенный HMR
- Быстрая сборка
- Современный tooling
- Лучшая производительность

### 5. **Tailwind CSS**
**Проблема**: Нужна быстрая разработка UI  
**Решение**: Tailwind CSS utility-first подход  
**Преимущества**:
- Быстрая разработка
- Консистентный дизайн
- Маленький bundle size (tree shaking)
- Легко кастомизировать
